## 关系类型推导（生成前先完成此步）

在生成关系之前，根据上方的**世界来源、主要类型、世界约束和角色构成**，推导出适合本世界的社会关系维度和对应的关系类型词汇。

关系类型必须反映本世界特有的社会结构、权力体系和文化语境，而非套用通用标签。不同世界的关系词汇应有本质差异：
- 封建王朝世界的权力关系 ≠ 魔法学院世界的师生关系 ≠ 星际军事世界的指挥关系
- 关系类型标签应让读者一眼能感受到"这是哪个世界"

```
  }
}
```

## 输出要求

输出一个 JSON 数组，每个元素对应一条有向关系边。

1. **端点 ID 严格绑定**：`edge.from_id` 和 `edge.to_id` 必须使用上方角色列表中的 ID（如 `e:world_name:char:001`），绝不能使用角色名字或其他格式。
2. **禁止自环**：`edge.from_id != edge.to_id`。
3. **全角色覆盖**：每个角色必须至少出现在一条关系的任一端点，不能有孤立角色。
4. **核心角色密度**：`[core]` 重要度的角色必须参与 ≥ 2 条关系（可以是 from 或 to）。
5. **关系类型语义**：`edge.type` 必须是稳定的身份或社会关系标签，能回答"他们之间是什么关系"，而非"他们做了什么"。禁止使用事件、动作或场景描述作为 type 值。
   **优先使用描述两人纽带的对称标签**（描述连接本身，而非某一端的立场），词汇应来自本世界的文化语境，而非套用其他世界或现代通用标签。
6. **关系类型多样**：`edge.type` 至少涵盖 3 种不同类型，覆盖本世界中存在的不同社会维度（权力、情感、对立等）。
7. **单向与双向的选择**：
   - 若关系对两端语义相同，用**一条** `direction="双向"` 的边，不要拆成两条单向边，也不要用两个互逆的标签分别描述。
   - 只有当 A→B 与 B→A 的关系类型或语义明显不同时，才分别用两条 `direction="单向"` 的边。
   - 禁止：对同一对角色生成相同 type 的两条单向边——应合并为一条双向边。

输出格式示例：
```json
[
  {
    "edge": {
      "id": "",
      "from_id": "e:world_name:char:001",
      "to_id": "e:world_name:char:003",
      "type": "监视",
      "direction": "单向"
    }
  }
]
```
